## Что сделано (по запросам владельца)

1. **Приложение на Mac, мультиплатформенный стек** — Tauri 2 + React/Vite, ядро на Rust
   (`crates/rmon-core`), CLI `rmon`, MCP-сервер `rmon mcp` (`crates/rmon-mcp`, docs/CLAUDE_CODE.md).
   Установка: `scripts/install-macos.sh` (DMG — `--dmg`).
2. **Enterprise / SSOT** — один цикл сбора `Monitor` на окно, MCP и CLI; политика снятия — данные
   (встроенное ∪ `[guard] never` ∪ конфиг); TS-типы генерирует ts-rs из Rust, подписи и эталон
   форматирования — тоже из Rust (`apps/rmon-app/src/bindings`, CI сверяет); правило фильтра —
   `ProcessRow::matches`; настройки пишутся в config.toml через toml_edit с сохранением комментариев.
3. **Вид списком, группы, подробности процесса** (каталог, родители, потомки, график памяти),
   у сессий `claude` в списках виден проект; группа «Claude Code» отдельно от приложения Claude.
4. **Сторож памяти** (бывший `Hooks/memory-guard`) перенесён в `rmon_core::guard` с теми же
   сценариями тестов; работает в приложении, уведомления, переключатель в полосе вкладок и в трее,
   вкладки «Сторож» и «Настройки». Старый LaunchAgent выгружен по приказу владельца
   (plist → `*.disabled-by-rmon`, откат — `rmon guard restore`).
5. **Запуск при входе** (tauri-plugin-autostart, тихий старт с `--autostart`), **настройки из окна**.
6. **Linux/Windows отложены** — в ROADMAP, задел в ветке выше.
7. **Лёгкость**: окно было 417 МБ с утечкой 24 МБ/мин (пересоздание меню трея и `emit`), теперь
   `Channel` + перерисовка значка только при изменениях, кэш политики по личности процесса, темп
   сбора 2 с при видимом окне и 3 с при скрытом/свёрнутом. Замер скрытого: 1,1 % CPU, 37 МБ.
8. **Цифры как в Activity Monitor** — сверено синхронными замерами: «Занято» = всего − свободно −
   кэш файлов; добавлен сегмент «Прочее».
9. **Иконка** — шкала давления (`apps/rmon-app/assets/icon.svg`, `npx tauri icon` из него).
10. **Почему сторож «не снял»** (вопрос с фото 19:40) — упёрся в предел 6 снятий/10 мин после шести
    снятий подряд; теперь при упоре — уведомление. **Журналы хранятся 24 ч** (`[logs]`), лента
    состояния `timeline.jsonl` раз в минуту — для разбора задним числом.

## Открыто (по приоритету)

1. **Полка памяти**: за первые 10 минут 38 → 51 МБ (заполняются история анализа 10 мин и график
   15 мин). Замерить через 20–30 минут работы, что рост остановился:
   `footprint $(pgrep -x rmon-app) | grep phys_footprint` раз в минуту.
2. **Снятие кнопкой в окне** вживую не прожато автоматикой (фоновый набор текста не доходит до
   WebView). Путь тот же, что у CLI/MCP (`MonitorHandle::kill`), он покрыт тестами и пробами.
   Проверить руками: `sleep 900 &`, в «Процессах» фильтр `sleep 900`, «Снять» → «Всё равно снять».
3. **Первый пустой экран** после одной из установок не воспроизвёлся; добавлен аварийный экран с
   текстом ошибки — если повторится, причина будет видна в окне.
4. ROADMAP «Позже»: группировка XPC-хелперов (WebContent) по ответственному приложению
   (`responsibility_get_pid_responsible_for_pid`), поле срока журналов во вкладке «Настройки».
5. Linux/Windows — по ROADMAP, перебазировать ветку платформ на `main`.

## Решения владельца, которые нельзя терять

- Работы — только в `main`, ничего не теряется по ворктри; решения без костылей, SSOT.
- Сначала Mac; Linux/Windows — позже.
- Сторож — только через приложение; старый memory-guard не возвращать без слова владельца.
- Приложение должно быть лёгким (цели: окно < 100 МБ, CPU в покое < 2 %).
- Тяжёлые прогоны на машине ставит в очередь хук «Сторож машины» — ждать и повторять, не обходить.
