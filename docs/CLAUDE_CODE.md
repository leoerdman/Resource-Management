# rmon в Claude Code (MCP)

`rmon mcp` — MCP-сервер на stdio. Через него Claude Code видит память и процессы Mac, получает
предложения, что снять, и снимает процессы через защитный слой `rmon-core`. Сам сервер ничего не
снимает: только по вызову `kill_process`, и только с правилами политики (см. ниже).

Сервер лёгкий: один фоновый поток снимает память раз в 5 с и держит окно истории 15 минут
(рост считается по минутам, а не по секундам). RSS сервера — 12 МБ на старте, ~20 МБ через 5 минут
(окно истории заполняется).

## Сборка

```sh
cd "<путь к репозиторию>"
CARGO_BUILD_JOBS=4 cargo build --release -p rmon-cli   # бинарь target/release/rmon, подкоманда `rmon mcp`
# или отдельный бинарь сервера (то же самое):
CARGO_BUILD_JOBS=4 cargo build --release -p rmon-mcp   # target/release/rmon-mcp
```

## Подключение

Один раз, на уровне пользователя (сервер доступен во всех проектах):

```sh
claude mcp add --scope user rmon -- "<абсолютный путь к репозиторию>/target/release/rmon" mcp
```

Проверка: `claude mcp list` — у `rmon` статус connected; в сессии `/mcp` показывает шесть инструментов.
Удалить: `claude mcp remove --scope user rmon`.

Переменные окружения (необязательно, задаются через `claude mcp add -e ИМЯ=значение`):

| Переменная | Что | По умолчанию |
|---|---|---|
| `RMON_GUARD_LOG` | журнал memory-guard | `~/Programming - Main/Hooks/memory-guard/log/events.jsonl` |
| `RMON_ACTIONS_LOG` | журнал действий rmon | `~/Library/Logs/rmon/actions.jsonl` |
| `RMON_CONFIG` | настройки (пороги, политика) | `~/.config/rmon/config.toml` |

Протокол — stdout; логи и ошибки сервера — только stderr.

## Инструменты

Описания для модели — по-английски; ответ — текст по-русски для человека плюс та же информация
структурой (`structuredContent` по `outputSchema`).

| Инструмент | Аргументы | Что даёт |
|---|---|---|
| `memory_overview` | — | давление, занято/всего, app/wired/сжато/кэш/свободно, своп; тренд занятого, сжатого и свопа за окно; топ-10 приложений; топ-5 подозреваемых; текущая зона memory-guard |
| `list_processes` | `sort` = `mem`\|`cpu`\|`growth`\|`pid` (mem), `limit` 1–500 (25), `filter`, `group_by_app` (false) | процессы (или приложения) с памятью, CPU, ростом в МБ/мин и политикой снятия; `filter` — подстрока имени, приложения, пути или строки запуска, число — ещё и pid |
| `process_details` | `pid` | строка запуска, рабочий каталог, родители до launchd, потомки с суммой памяти, ряд памяти за окно, политика и её причина, вердикт подозреваемого |
| `suggest_cleanup` | `min_score` 0–100 (30) | «можно освободить ≈ X без подтверждения, ещё Y — с подтверждением» и список подозреваемых с причиной, объёмом и политикой |
| `kill_process` | `pid`, `reason`, `hard` (false), `confirm` (false), `dry_run` (false) | снятие через защитный слой: сверка личности → SIGTERM → 5 с → SIGKILL (`hard` — сразу SIGKILL); каждое действие и отказ — в журнал действий с `requested_by: "mcp"` |
| `guard_events` | `limit` 1–200 (20) | последние события memory-guard (зоны, его снятия, пределы), новые сверху; нет журнала — пустой список |

Подозреваемые появляются через ~5 с после запуска сервера (нужен второй снимок), рост процессов —
через ~15 с (три снимка). Claude Code запускает сервер в начале сессии, так что к первому вопросу всё
уже посчитано.

### Политика снятия

- **защищён** — никогда, даже с `confirm`: ядро и launchd, системные пути, WindowServer, loginwindow,
  сам rmon, процессы других пользователей и root, хуки сторожа машины.
- **с подтверждением** — приложения владельца и их хелперы (браузеры, Claude, M Code, Telegram,
  редакторы, сессии `claude` CLI, mcode-engine), системные утилиты, всё из `never` memory-guard.
  Без `confirm=true` — отказ со статусом `needs_confirmation`. Описание инструмента прямо велит
  модели **спросить владельца**, прежде чем повторить вызов с `confirm=true`.
- **можно снять** — dev-прогоны и прочее: снимается сразу.

Ошибки аргументов (`pid: "abc"`, `limit: 0`, пустая `reason`) приходят ошибкой вызова, сервер
продолжает работать.

## Пример диалога

> **Вы:** разберись с памятью, ноут тормозит
>
> **Claude** вызывает `memory_overview`:
> «Память: занято 19,4 ГБ из 24 ГБ (80,9 %), давление повышенное, доступно 38 %. … Своп 18,7 ГБ из
> 20 ГБ. Тренд за 15 мин: … своп +1,2 ГБ (+80 МБ/мин) … Сторож памяти: зона red …»
>
> затем `suggest_cleanup`:
> «Можно освободить ≈ 3,1 ГБ без подтверждения, ещё 4 ГБ — с подтверждением.
>   1. [80] tsgolint (90138) — занимает 1,5 ГБ … ; можно снять
>   2. [61] Telegram Lite (51167) — занимает 2,2 ГБ … ; с подтверждением: Telegram …»
>
> **Claude:** Своп растёт на 80 МБ/мин. Без вопросов могу снять tsgolint (1,5 ГБ) и два брошенных
> `node` (ещё 1,6 ГБ). Telegram держит 2,2 ГБ — закрыть его?
>
> **Вы:** tsgolint и node снимай, Telegram не трогай
>
> **Claude** вызывает `kill_process {pid: 90138, reason: "tsgolint 1,5 ГБ, своп растёт"}` и т. д. —
> «tsgolint (90138) снят SIGTERM, освободилось ~1,5 ГБ». Telegram не трогает.

Если модель попробует снять приложение без согласия, сервер откажет:
«Отказ: снятие 3979 (claude) требует подтверждения: сессия Claude Code … Нужно согласие владельца:
спросите его, можно ли снять именно этот процесс, и только после ответа «да» повторите с confirm=true.»

## Ручная проверка

```sh
printf '%s\n' \
 '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}' \
 '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
 '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' \
 '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"memory_overview","arguments":{}}}' \
 '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"kill_process","arguments":{"pid":1,"reason":"probe"}}}' \
 | (cat; sleep 3) | ./target/release/rmon mcp
```

Ответ на `id: 4` — `isError: true`, статус `refused_protected`: «снятие 1 … запрещено: ядро системы».
